1. BACKEND: 500 ERROR FIX (joinedload)
================================================================================
File: backend/services/report_service.py
Functions: _personal_attendance_report(), _instructor_delay_report()

ROOT CAUSE:
  Both functions call _build_student_rows() which accesses cls.faculty
  (the Class.faculty relationship) to display faculty names. However,
  the SQLAlchemy query only had joinedload(Class.subject), causing a
  lazy-load attempt on an expired session = 500 Internal Server Error.

FIX:
  Added joinedload(AttendanceLog.class_).joinedload(Class.faculty) to:
  - _personal_attendance_report() query (~line 1525)
  - _instructor_delay_report() query (~line 1640)

PATTERN FOR DEPT HEAD MODULE:
  Any report handler that uses _build_student_rows() MUST eager-load
  both Class.subject AND Class.faculty. The dept module should follow
  this same pattern when accessing cross-faculty reports.

2. BACKEND: FACULTY CORE METRICS ENGINE
================================================================================
File: backend/services/report_metric_service.py
Added functions (appended after line 667):

  _resolve_faculty_class_ids(db, user_id, class_id=None)
      Returns list of class IDs taught by the faculty member.
      If class_id is provided: returns [class_id] if faculty owns it.
      If class_id is None: returns ALL class IDs for Classes with
      faculty_id == user_id.

  compute_faculty_core_metrics(db, user_id, date_from, date_to, class_id=None)
      Full attendance computation for a faculty member.
      Returns dict with 20+ fields:
        sessions_attended, sessions_conducted, sessions_expected,
        on_time_entries, late_entries, punctuality_rate,
        real_time_attendance_rate, semester_progress_attendance_rate,
        early_exits, break_count, avg_break_minutes,
        total_break_minutes, consistency_index, data_completeness_score,
        session_count_for_confidence

      Logic mirrors student metrics but scoped to faculty:
      - Queries AttendanceLog where user_id = faculty AND class_id in taught classes
      - ENTRY action = attendance, is_late flag = late detection
      - Pairs BREAK_OUT/BREAK_IN for break duration computation
      - Uses _compute_expected_sessions() with SessionException exclusions
        (CANCELLED/HOLIDAY excluded, ONLINE excluded, ONSITE forced valid)
      - consistency_index = real_time_attendance_rate * 0.7 + punctuality_rate * 0.3

  compute_faculty_session_count_reference(db, user_id, date_from, date_to, ...)
      Returns {"report_window": {...}, "whole_semester": {...}} where each has
      attended, conducted, expected counts.
      Uses department semester dates when available.
      Calls _compute_counts_for_range() (shared student helper).

  build_faculty_summary_metrics(metrics, date_from, date_to, class_id=None)
      Builds 4 metric cards from computed metrics:
        1. real_time_attendance_rate — Numerator: sessions_attended / Denominator: sessions_conducted
        2. semester_progress_attendance_rate — Numerator: sessions_attended / Denominator: sessions_expected
        3. punctuality_rate — Numerator: on_time_entries / Denominator: sessions_attended
        4. consistency_index — Formula: 0.7 * attendance_rate + 0.3 * punctuality_rate
      Each card includes: metric_name, value, formula, explanation,
      confidence (via compute_confidence_label), numerator, denominator, data_window

CONFIDENCE SCORING:
  compute_confidence_label(session_count, data_completeness_score):
    HIGH: session_count >= 20 AND completeness >= 0.95
    MEDIUM: session_count >= 8 AND completeness >= 0.85
    LOW: anything below

PATTERN FOR DEPT HEAD MODULE:
  The dept head module can call compute_faculty_core_metrics() for any
  faculty member under their department. The function accepts user_id +
  date range + optional class_id filter. Department-level aggregation
  should loop over department faculty and aggregate metrics.

3. BACKEND: FACULTY REPORT ENVELOPE UPDATE
================================================================================
File: backend/services/report_service.py
Function: get_faculty_report_envelope()

CHANGES:
  - Added imports: compute_faculty_core_metrics, build_faculty_summary_metrics,
    compute_faculty_session_count_reference, compute_confidence_label
  - Added FACULTY_PERSONAL_REPORT_ALIASES set to detect personal reports:
    {"PERSONAL_DAILY", "PERSONAL_WEEKLY", "PERSONAL_MONTHLY",
     "PERSONAL_SEMESTER", "PERSONAL_CONSISTENCY", "INSTRUCTOR_DELAY",
     "BREAK_LOG", "ABSENT_LOG"}
  - When report_type is in FACULTY_PERSONAL_REPORTS or FACULTY_PERSONAL_REPORT_ALIASES:
    1. Calls compute_faculty_core_metrics() for the faculty user
    2. Calls build_faculty_summary_metrics() to produce 4 metric cards
    3. Calls compute_faculty_session_count_reference() for session counts
    4. Passes faculty_metrics to generate_faculty_role_insights()
  - Falls back to old _build_summary_metrics_from_rows() on error

ENVELOPE STRUCTURE:
  {
    "success": true,
    "meta": {...},
    "summary_metrics": [4 metric card objects],
    "insights": [medium-high confidence insight objects],
    "session_count_reference": {"report_window": {...}, "whole_semester": {...}},
    "visual_rows": [...],
    "rows": [...]
  }

PATTERN FOR DEPT HEAD MODULE:
  The dept head envelope should follow the same structure. It can reuse
  compute_faculty_core_metrics() per-faculty and aggregate. The dispatch
  dictionary pattern (FACULTY_CLASS_REPORTS, FACULTY_PERSONAL_REPORTS)
  should be mirrored for DEPT_REPORTS with department-scoped queries.

4. BACKEND: MEDIUM-HIGH CONFIDENCE INSIGHT FILTER
================================================================================
File: backend/services/role_based_analytics_service.py
Function: generate_faculty_role_insights()

CHANGES:
  - Added parameter: faculty_metrics: Optional[Dict] = None
  - When faculty_metrics is provided, computes confidence per insight:
      session_count = faculty_metrics.get("session_count_for_confidence", 0)
      completeness = faculty_metrics.get("data_completeness_score", 0)
      Thresholds: HIGH (>=20 sessions + >=0.95 complete),
                  MEDIUM (>=8 sessions + >=0.85 complete), else LOW
  - Filter at return: only insights with confidence in ("HIGH", "MEDIUM")
  - When faculty_metrics not provided: defaults to LOW confidence (filtered out)

INSIGHT TYPES GENERATED:
  FACULTY_PARTICIPATION_DISTRIBUTION, FACULTY_PUNCTUALITY_CLUSTER,
  FACULTY_ANOMALY_RISK_CLUSTER, FACULTY_ENGAGEMENT_COMPLETION,

  FACULTY_SECTION_COMPARISON, FACULTY_STUDENT_RANKING_SUMMARY,
  FACULTY_SECTION_RANKING_DEPTH

PATTERN FOR DEPT HEAD MODULE:
  Department insights should use generate_department_role_insights() and
  apply the same confidence filter. Pass aggregated department metrics
  for proper confidence scoring.

5. BACKEND: REAL AVERAGE ATTENDANCE COMPUTATION (DASHBOARD)
================================================================================
File: backend/api/routers/faculty.py
Function: get_faculty_dashboard_stats()

CHANGE:
  Replaced hardcoded `average_attendance = 85.0` with actual computation:
  - Gets department semester dates (semester_start_date, semester_end_date)
  - Falls back to 120 days ago if no semester dates
  - Calls _compute_expected_sessions() from report_metric_service
  - Counts distinct (class_id, date) ENTRY logs for the faculty user
  - average_attendance = (attended / expected) * 100, rounded to 1 decimal

DEPENDENCIES:
  - _compute_expected_sessions from services.report_metric_service
  - SessionException model for exception filtering

9. ARCHITECTURE NOTES FOR DEPARTMENT HEAD MODULE ADOPTION
================================================================================

REPORT ENVELOPE PATTERN:
  All roles (student, faculty, dept head) should return the same envelope:
  {success, meta, summary_metrics, insights, session_count_reference, visual_rows, rows}

METRICS REUSE:
  - Student: compute_student_core_metrics() (exists)
  - Faculty: compute_faculty_core_metrics() (new)
  - Dept Head: Should aggregate faculty metrics across department

INSIGHTS REUSE:
  - Student: generate_student_role_insights() (exists)
  - Faculty: generate_faculty_role_insights() (updated with confidence)
  - Dept Head: generate_department_role_insights() (exists, needs confidence filter)

CONFIDENCE PATTERN:
  All insights should go through confidence scoring before display.
  Minimum display threshold: MEDIUM.
  Pass computed metrics to insight generators for proper confidence.

REPORT TYPE DISPATCH:
  Each role has a dispatch dictionary mapping report_type strings to handler functions.
  Dept head reports should be defined in DEPT_REPORTS dict following the same pattern.

FRONTEND TAB PATTERN:
  - Define report arrays at module level (const REPORTS = [...])
  - Tab state controls which array is active
  - resolveFacultyReportType() maps frontend IDs to backend codes
  - Column configs are tab-aware: getColumnConfig(reportType, tab)
  - Auto-fetch on filter change via useEffect dependency array

SESSION COUNT REFERENCE:
  Shows users how many sessions were attended vs conducted vs expected.
  Split into "Report Window" (date range of current report) and "Whole Semester".
  Dept head should show department-aggregated counts.
